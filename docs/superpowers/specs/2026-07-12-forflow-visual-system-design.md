# ForFlow 官网视觉系统收敛设计

日期：2026-07-12  
状态：待用户书面审阅  
适用范围：首页、企业服务、场景诊断与结果、案例与博客、HR 场景地图、联系页、受邀访问页

## 1. 目标

保留 ForFlow 现有的黑白绿、粗体中文、技术感与视觉张力，同时解决全站每个模块都在高亮的问题。

本次改造不追求更“素”，而是建立清楚的视觉音量：

- 品牌首屏负责吸引注意。
- 业务内容负责快速理解。
- 产品界面负责说明怎么使用。
- 技术图负责说明系统怎么工作。
- 案例证据负责建立信任。
- 品牌动效负责关键转场，不打断正文阅读。

## 2. 参考原则与边界

参考来源：

- [TSH Digital Product Design](https://tsh.io/digital-product-design)：吸收“一个强观点，后续用安静的方法与证据承接”的层级方式。
- [Sana Learn Leadership Development](https://sanalabs.com/products/sana-learn/solutions/leadership-development)：吸收“真实产品视觉、大量留白、高饱和色集中在产品和行动”的表达方式。

不复制两家的字体、配色、圆角、插画或组件。ForFlow 继续使用自己的黑白绿品牌语言和现有内容结构。

## 3. 高亮预算

每个页面在设计前分配高亮预算，用完后不能继续增加同级元素。

| 类型 | 页面上限 | 使用位置 |
| --- | ---: | --- |
| Hero 级标题 | 1 | 页面第一屏 |
| 实心绿色主 CTA | 每个视口 1 | 当前最重要的下一步 |
| 黑色高权重区域 | 1 | 案例证据、关键指标或决策结论 |
| 英文全大写 Kicker | 2 | Hero 和一次重要章节转场 |
| 描边大字 | 1 组 | 仅品牌首页 Hero，可不用在普通内页 |
| 绿色关键数字 | 每区 1–3 个 | 经过解释的指标或进度 |

如果同一视口已经存在绿色主 CTA，其他按钮使用白底描边或文字链接。绿色不用于普通卡片底色。

## 4. 排版层级

### 桌面端

| 层级 | 建议字号 | 用途 |
| --- | --- | --- |
| 首页 H1 | `clamp(68px, 6.5vw, 92px)` | 唯一品牌主张 |
| 内页 H1 | `clamp(52px, 5vw, 68px)` | 服务、案例、工具标题 |
| 章节 H2 | `clamp(36px, 3.5vw, 48px)` | 章节核心判断 |
| 卡片 H3 | 22–30px | 服务、场景、交付物 |
| 正文 | 17–20px | 说明与叙事 |
| 辅助文字 | 13–15px | 来源、状态、补充说明 |

### 移动端

| 层级 | 建议字号 |
| --- | --- |
| 首页 H1 | 48–58px |
| 内页 H1 | 40–48px |
| H2 | 30–36px |
| H3 | 21–26px |
| 正文 | 16–18px |

普通 H2 不使用 Hero 级行距、描边和超大上下留白。长标题必须按语义换行，不依赖固定 `<br>` 适配所有宽度。

## 5. 色彩与表面

### 绿色

绿色只表达四类信息：

1. 当前主要行动。
2. 已选择、已完成或正在进行的状态。
3. 关键结果或指标。
4. 技术图中的有效流向。

绿色不再用于整张普通内容卡、无交互装饰块或大量背景渐变。

### 黑色

黑色用于建立“这是关键证据或决策”的重量：

- 结果与指标。
- 案例中的关键结论。
- Agent 权限、数据边界和运行机制。

一个页面只保留一个黑色高权重区。页头黑色品牌条不计入该额度。

### 圆角与边框

- 大容器：18px。
- 普通卡片：12px。
- 按钮和状态标签：允许胶囊形。
- 普通章节不再默认放进圆角卡片。
- 优先使用留白、细分隔线和网格对齐完成分组。

## 6. 四类视觉资产的职责

四类资产全部保留，但不在同一屏同时争抢注意。

### 6.1 业务摄影

职责：说明人在什么业务现场、处理什么工作。

使用位置：

- 首页 Hero。
- 服务页首屏或团队经验区，二选一。
- 案例页的真实工作现场。
- 联系页最多一张城市或沟通场景图。

要求：真实工作动作优先，避免泛化办公摆拍、握手、会议合影和只有氛围没有任务的图片。

### 6.2 产品界面

职责：说明用户怎样操作，以及完成后得到什么。

使用位置：

- AI 场景诊断器。
- 诊断结果与排序。
- HR 场景地图。
- 报告、评估工作台和未来客户工作区。

要求：只展示真实或已经设计确认的界面；不能把不可操作的营销图伪装成产品截图。移动端优先展示当前操作，而不是整台设备外壳。

### 6.3 技术图

职责：说明数据、知识、权限、系统、人工审批和回退机制如何连接。

使用位置：

- 数据治理服务。
- 企业 Agent 与工作流服务。
- 技术型案例详情。
- 手册中的架构与决策章节。

统一规则：

- 相同线宽、节点半径、字体和箭头样式。
- 绿色只表示通过、有效流向或当前选中路径。
- 黑色表示系统边界与关键节点。
- 灰色表示背景系统、候选路径或未激活状态。
- 每张图只回答一个问题，复杂图必须配一句结论。

### 6.4 品牌动效

职责：建立品牌记忆，确认进入、完成或阶段变化。

使用位置：

- 首页首次进入的轻量品牌转场。
- 诊断完成后进入结果页。
- 重要项目里程碑或报告生成确认。

限制：

- 不用于普通正文逐段淡入。
- 不得延迟 H1、正文、表单和主要按钮的可读性。
- 关键内容初始透明度为 1；只移动装饰元素或局部图形。
- 单次入场 180–420ms，错峰间隔 40–80ms。
- 支持 `prefers-reduced-motion`，关闭非必要移动、缩放和循环动画。

## 7. 页面级应用

### 首页

保留五个核心段落：

1. Hero：品牌主张、业务摄影、一个绿色诊断 CTA。
2. 业务问题：安静的白底列表或分栏，不使用六张高亮卡。
3. 服务路径：用编号、周期和交付物比较五项服务。
4. 案例证据：页面唯一黑色高权重区。
5. 行动入口：诊断器、联系或手册，明确主次。

方法论和工具资源并入相关段落，不再各自形成完整 Hero。

### 企业服务

- 首屏保留一个明确判断、适用条件和主 CTA。
- 内页 H1 降至 52–68px。
- 服务结果、范围、流程和交付物采用不同结构，不全部使用相同圆角卡片。
- 每页只允许一个深色高权重区，优先给证据或项目结果。

### 场景诊断与结果

- 以产品界面为主，不叠加无关摄影。
- 第一屏尽快露出第一个可选项。
- 结果页先显示一个首选建议、推荐理由、准备缺口和下一步。
- 其他服务折叠为备选路径，避免重新制造选择压力。

### 案例与博客

- 列表页用证据类型、行业和场景筛选，不靠不同颜色区分来源。
- 详情页首屏提供管理层摘要、证据类型和来源边界。
- 业务案例优先摄影，技术案例优先技术图，不同时堆两套主视觉。
- 超长案例增加目录、阶段分隔和可折叠技术附录。

### HR 场景地图

- 保留产品界面式结构和横向阶段导航。
- 绿色表示当前阶段和关键行动。
- 场景内容使用白底、线框与分栏，不再每个子项独立高亮。

### 联系页与门禁页

- 联系页主角是表单；城市摄影降为次级信息，只保留一张。
- 门禁页继续保持单任务，不增加产品介绍卡和多入口导航。

## 8. 设计系统实现边界

视觉系统先通过 CSS token 与组件变体落地，不为每个页面单独写一套样式。

建议新增或统一：

- 排版 token：`--type-hero`、`--type-page-title`、`--type-section`、`--type-card`。
- 表面 token：`--surface-paper`、`--surface-muted`、`--surface-proof`。
- 圆角 token：`--radius-card: 12px`、`--radius-panel: 18px`。
- 组件变体：`section--quiet`、`section--proof`、`cta--primary`、`cta--secondary`。
- 资产组件：`business-photo`、`product-shot`、`technical-diagram`、`brand-motion`。

已有资产优先复用。缺少符合职责的图片时，再单独使用 Image Gen 生成；生成前必须先确定槽位尺寸、裁切、人物动作、业务环境和品牌色密度。

## 9. 降级与异常处理

- 图片加载失败时保留尺寸与文字说明，不显示空白大色块。
- 视频不可播放时显示正式 poster 图，不出现浏览器默认错误文字。
- JavaScript 未执行时，正文、导航、表单与主要 CTA 仍然可见。
- 减少动效模式下不影响信息层级和完成任务。
- 诊断结果、表单和案例来源不依赖颜色作为唯一状态信号。

## 10. 验收标准

### 视觉

- 任意视口中最多一个实心绿色主 CTA。
- 任意页面最多一个黑色高权重内容区。
- 除首页 Hero 外，不出现 68px 以上章节标题。
- 英文全大写 Kicker 每页不超过两处。
- 同一屏不同时出现摄影、产品界面、复杂技术图和品牌动效四类主视觉。
- 普通内容分组优先使用留白和分隔线，而不是全部卡片化。

### 交互与可访问性

- 390px、768px、1280px 和 1440px 视口无横向溢出。
- 移动端进入诊断后，首个可操作选项在一屏内可见或明确露出。
- 键盘焦点、选中状态和错误状态不只依赖绿色。
- `prefers-reduced-motion` 下所有核心流程可完成。
- 正文与背景、按钮与背景满足 WCAG AA 对比度。

### 内容与资产

- 每张摄影、产品图和技术图都有明确的业务问题或说明目的。
- 案例来源、团队经验和公开资料保持显式区分。
- 技术图旁必须有一句可以独立理解的结论。
- 品牌动效不重复播放并干扰长文阅读。

## 11. 实施顺序

1. 统一 token、标题层级、圆角和按钮变体。
2. 改造首页结构与高亮预算。
3. 改造诊断结果页，使其只有一个首选建议。
4. 统一五项服务页的首屏、证据区和长页节奏。
5. 统一案例列表、案例详情和技术图规则。
6. 收敛 HR 场景地图、联系页和门禁页。
7. 逐页做桌面、移动、减少动效和键盘 QA。

## 12. 非本轮目标

- 不更换 ForFlow Logo。
- 不改变黑白绿的品牌核心色。
- 不重写所有业务文案。
- 不新增账号系统、客户工作区或后台产品。
- 不为了统一而删除摄影、产品界面、技术图或品牌动效中的任何一类。
