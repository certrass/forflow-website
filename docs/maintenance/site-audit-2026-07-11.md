# ForFlow 整站文案与设计审计（2026-07-11）

## 本轮目标

让企业客户在第一次浏览时，能依次回答四个问题：

1. ForFlow 解决什么业务问题？
2. 我现在应该从哪一步开始？
3. 每项服务会交付什么、需要多久？
4. 如何带着一个具体问题开始沟通？

本轮参考 TSH 的直接服务表达，以及 Sana Labs 的留白、单屏单任务和克制强调色；只学习信息路径，不复制页面形状。

## 公网安全审计

### 已确认的线上 P0

- 生产环境当前仍直接发布仓库根目录，`/build_site.py`、`/tests/gate_runtime_check.mjs`、`/docs/maintenance/site-governance.md` 均返回 `200`。
- 历史门禁测试源码曾包含生产访问码，因此旧访问码必须视为已经泄露；只部署代码、不轮换 `SITE_GATE_PASSWORD` 不能完成修复。

### 本地已完成的修复

- Netlify 发布目录改为构建后的 `dist/`，只复制根级公开页面、运行脚本和页面实际引用的资源；源码、测试、维护文档、模板和内部 PDF 不进入发布包。
- Edge 门禁默认保护所有资源，不再只拦 HTML；只放行门禁必需资源、登录函数和动态二维码路径。
- 登录改为同源 JSON POST，限制请求体与访问码长度，拒绝已泄露旧码，并加入每 IP / 域名每分钟 5 次的 Netlify 函数限流。
- 授权 Cookie 改为 `__Host-ff_gate`、`HttpOnly`、`Secure`、`SameSite=Lax`，有效期 24 小时；`landing.html?reset=1` 可以清除授权。
- HTML/PDF 响应统一补充 CSP、禁止嵌入、`no-referrer`、`nosniff`、`noindex` 与私有内容 `no-store`。
- HR 集成图标改为本地托管；咨询草稿和诊断答案不再长期留在浏览器本地存储。

### 上线前必须完成

1. 在 Netlify 生成并设置一个全新的 `SITE_GATE_PASSWORD`，旧码永久停用。
2. 部署当前 `dist/` 构建；禁止再使用 `netlify deploy --dir . --prod`。
3. 检查 Deploy log 是否识别函数限流配置；登录后确认旧源码路径为 404，未登录时站点资源统一回到门禁页。
4. 如果 Cloudflare 代理已开启，部署后清理缓存，并复核 CSP、Cookie 与缓存响应头。

## 已实施的主要调整

- 首页 Hero：删除“真正卡住业务”一类抽象口号，改为具体工作消耗、判断维度、小试点和停止条件。
- 首页首帧：文字不再等待淡入完成才出现；量化入口从五项压到四项，减少首屏选择负担。
- 问题入口：用“客服被重复问题拖住”“资料很多，答案找不到”等业务症状取代部门式分类。
- 企业服务：将说明压缩为一屏内可扫描的服务路径，并把描述改成交付物和使用场景。
- 服务详情：统一“适不适合做—怎么做—留下什么—证据能说明什么—如何咨询”的结构。
- 服务文案：把重复的“先……再……”“不是……而是……”改成直接陈述，咨询卡统一为“30 分钟确认范围”。
- 场景诊断：说明输出只是建议起点，并列出正式启动前仍缺的条件。
- 诊断结果：移动端将建议放在品牌视频前；视频高度限制在 230px 内，排序菜单同步 `aria-expanded`、`aria-hidden` 与 `aria-pressed`。
- 准备度与 HR：六题自测、进度和结果状态已回归；HR 六个标签页、证据说明与手机横向标签栏已回归，并继续压缩模板化表达。
- 案例页：去除“不只……也……”等公式化表达，明确案例的可参考范围。
- 联系页：标题、邮件说明和准备材料改为客户可直接行动的语言。
- 全站交互：为链接、按钮和表单控件补充统一的键盘焦点样式。
- 工具入口：在 701–900px 使用两列加跨栏，在 700px 以下改为等高单列，修复中间宽度下卡片一窄一空的问题。

## 证据边界

- TSH 首页已在 2026-07-11 重新捕捉。采用的是其“首屏一句话定位 + 明确适用时刻 + 具体交付速度 + 可信度证明”的信息路径，不复制其渐变背景与版式。
